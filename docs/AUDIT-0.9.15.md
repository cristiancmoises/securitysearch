# Security Search v0.9.15 — audit and measured validation

Prepared 2026-09-08 from the completed v0.9.14 checkout, whose Codeberg baseline is `0751f145ff7b68d1f9c070c8bd8af79cd7bff717`. This is a source/configuration audit, automated regression suite, offline HTTP integration and deployment simulation. It is not a penetration test, dependency/CVE certification or proof of VPS readiness.

## Executed validation

- **106 PHP files:** syntax checks pass under PHP 8.3.
- **Nine PHP regression suites:** general behavior, Invidious/Binternet adapters, Google transport, API/provider selection, proxy transport, configuration generation, stream bounds, no-JavaScript contracts and encrypted image flow all pass.
- **Python:** syntax checks, stateful deployment simulations and actual localhost HTTP controller suite pass.
- **HTTP controller checks:** defaults have no Refresh; Play/Pause preserves results without another provider search; tampered query fields are ignored; date filters survive; six concurrent next requests advance once; ten-transition stop, interval clamp, paused manual step, empty/final pages, provider 503 and expired-frame 410 all pass. Server output contained no PHP warning, fatal, deprecation or parse diagnostic.
- **CSS:** all bundled stylesheets and the homepage inline stylesheet parse, including nested media/supports rules, using temporary authoring dependency tinycss2 1.4.0. No new runtime dependency was added.
- **Shell/fish:** fish 3.7 syntax passes for both delivered copies; shellcheck passes for the test runner, release script and Docker entrypoint. Generated rollback scripts pass `sh -n`.
- **Packaging gate:** required source/assets/fish script, clean committed source, no browser JS, no private API-key files, no prompts and no generated bytecode/cache payloads.

Reproduce the regression and HTTP checks with `sh scripts/test.sh`. HTTP tests copy production controllers/libraries/templates into a temporary tree and replace only the provider there with an offline fixture; they neither alter actual scraper source nor query outside services.

## Performance

Final local sample: PHP 8.3 CLI HTTP server with four workers; loopback; **50 homepage requests, four clients, 50/50 successful**. Median **2.11 ms**, p95 **5.59 ms**, about **1,389.58 requests/second** in this short sample, 1,118,300 response bytes. These numbers exclude NPM/TLS, Internet latency, media downloads and provider searches. They are neither a VPS capacity estimate nor a controlled before/after speedup claim.

Synthetic 1,000-iteration checks:

| Work | Median | p95 | Peak PHP allocation |
|---|---:|---:|---:|
| Render homepage | 0.0550 ms | 0.0691 ms | 2 MiB |
| Parse 50 Invidious videos | 0.0758 ms | 0.1084 ms | 2 MiB |
| Parse 50 Binternet images | 0.2486 ms | 0.3048 ms | 2 MiB |

The retained raw-template cache produced identical bytes. For 1,000 homepage reads/compactions, uncached work took 41.745 ms and warm-cache work 2.302 ms. This was already present in the baseline. Removing scripts and limiting result count reduces the page's potential browser work; end-to-end image bandwidth and visual rendering were not benchmarked.

## Remaining limits and deployment checks

1. **No true infinite scrolling.** The no-JavaScript implementation uses full-page Refresh navigation. It replaces pages, can run in background tabs, and depends on browser settings. Browser/device visual testing, accessibility-tool testing and actual Refresh timing were not performed. These cannot be certified by HTTP tests.
2. **Google availability remains external.** The application does not bypass challenges, silently change providers or keep retrying a rate-limited search. Google's [network traffic guidance](https://support.google.com/websearch/answer/86640?hl=en) explains why shared/automated traffic may be restricted. The local 30-second cooldown is not a promise of upstream recovery.
3. **Result and media limits are visible tradeoffs.** Only the first 24 entries of a larger provider page are displayed, with the omitted count disclosed. Binternet extension filters may leave pages empty. Original media can consume substantially more bandwidth; the validated proxy can refuse formats/size limits. Native lazy loading is not the only request bound, because browsers may disable it when scripting is off.
4. **Snapshot URLs are capabilities.** Anyone with a valid frame URL can read that short-lived snapshot. APCu payloads are encrypted, but NPM must omit query strings too. Proxy forwarding can also make users share the per-address quota. Restarts/cache eviction stop controls. No shared plaintext search-result cache was introduced.
5. **No Docker daemon/VPS access here.** The Alpine 3.24 image build, PHP 8.4/Apache/ImageMagick 7 behavior, actual Docker API cutover/rollback, mounted file permissions, NPM/TLS/firewall/logs and live provider searches remain unverified. Candidate checks run when the fish script is executed; they do not test every provider, codec or YouTube playback.
6. **Existing runtime policy is inherited.** The updater preserves live Docker capabilities/security options/limits instead of silently applying a fresh Compose profile. Shared runtime mounts that could mask the new policy fail preflight. Hard host/daemon failures or cleanup errors can still require the retained manual rollback command.
7. **Legacy provider scope remains.** Some older selectable adapters retain long or insufficiently bounded buffered responses; they were not all rewritten. The added Invidious/Binternet transport remains bounded to 12 seconds/2 MiB and Google retains its shared deadline. Favicon and raster-codec behavior still need the actual production image policy; this is not a CVE scan of a built image.

No remote Git push, SSH connection or production deployment was performed. [English deployment guide](OPERATIONS-0.9.15.md) · [Português](OPERATIONS-0.9.15.pt-BR.md).
