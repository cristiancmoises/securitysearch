# v0.9.18 — media, Google recovery, Reddit and UI audit

Prepared 2026-09-09 from v0.9.17 commit `b0dc22d`; asset/config marker **22**. This review covers the changed runtime/deployment paths and reruns the complete established source regression suite. It is not a penetration-test, accessibility certification or guarantee of upstream availability. Earlier transport and pagination audit context remains in [v0.9.17](AUDIT-0.9.17.md).

## Findings and changes

- **Google default recovery:** failed new HTML web/image searches try Brave once. Google gets a 12-second network budget and Brave at most 8 seconds within a shared 20-second absolute deadline. Existing CSE cooldown/bootstrap caching and configured egress restrictions remain. Header, filters and JSON identify the actual provider. Compatible filters and dates survive. Successful empty results, continuations, append requests, other providers and API calls retain their contract. Failed dual-provider searches still return HTTP 503 with explicit recovery; no fake results or successful timing is shown.
- Shared provider imports were corrected to avoid class redeclaration on fallback; Brave properties and required parameters no longer emit the affected PHP 8.3 deprecations. Brave transport now has a 4 MiB decoded-body limit, verified HTTPS, no redirect following and a shrinking deadline. Existing bounded challenge attempts share the fallback budget; there is no challenge solver or extra egress bypass. Tests cover deadline expiry before network execution. Provider identity and continuation parameters are checked before appending, including the string `npt=0` edge case.
- **Animated previews:** real GIF, animated WebP and APNG bytes pass through the validated proxy; a new image-only controller starts at most two loads and retains at most four active animations. It uses viewport/mutation events, with no polling, autoplay scroll or background retry. Offscreen/hidden/reduced-motion/Save-Data states restore posters. A separate Settings cookie can omit this controller independently of infinite scrolling. New cards register with the same controller, including a final provider page with no continuation.
- Automatic animation requests are limited to 8 MiB, 500 frames, 4096 px per side, 8 MP and 64 million aggregate frame pixels. The existing native viewer retains larger limits. Existing admission caps of three active validations and nine bounded waiters remain. Unsupported/static/malformed animation requests now return an empty 422 instead of a decodable error PNG that could be mistaken for successful animation. Failed automatic loads restore a still image without retries.
- Compressed first-frame extraction for GIF/WebP and the default PNG image for APNG allow still posters under the existing strict decoder frame-list limit. The decoder's raster/size/resource policy stays in place. A WebP first frame smaller than its full canvas can produce a cropped poster; the original animation bytes remain intact. Sources without supported URL/metadata hints cannot be inferred reliably; animated AVIF and video conversion are outside this release. Static WebP remains static. Brave's proposed motion URL may itself be static, in which case the poster remains available.
- **Reddit news:** the top service navigation gains Reddit. Local `/news` defaults to the latest r/news + r/worldnews posts, or related community posts for keywords through the fixed Redlib instance. Existing provider choices remain selectable. The adapter follows the official Redlib [search handler](https://github.com/redlib-org/redlib/blob/main/src/search.rs) and [post template](https://github.com/redlib-org/redlib/blob/main/templates/utils.html) contract. It uses bounded HTML parsing, escaped text, strict same-instance permalinks, fixed request routes and validated cursor reconstruction. Query prefixes that Redlib interprets as navigation are quoted. Empty and unavailable pages are distinguished, UTF-8 slugs are retained safely, and keyword-only sort/time filters are labeled accordingly.
- Redlib uses the existing fixed-service transport: HTTPS, DNS pinning/private-address checks, no redirects, a 12-second deadline and a 2 MiB body limit. Returned upstream URLs never become fetch destinations. The actual `libre.securityops.co` instance returned **503** during this release's availability check. Source-contract and HTTP fixtures pass; this is not evidence that live news is available.
- **UI:** four 14 px icons sit in one row inside the right edge of the search input. Reserved input padding prevents text overlap. Desktop targets are 28 px; coarse-pointer targets are 44 px. Accessible names and focus/hover labels remain. The homepage Wiki/Git footer strip has no background, border, shadow or blur. Tron and the centered “In Code We Trust.” message remain. The top News link still targets news.securityops.co, independently of the local News search tab.
- The two runtime scripts total **14,402 source bytes**: infinite scrolling 10,096 bytes / 3,249 gzip; motion 4,306 bytes / 1,377 gzip. Gzip is reproducible measurement, not a promise about server transfer compression. Only `/images` permits same-origin script/fetch. Other pages retain script/fetch blocking. Inline code, third-party dependencies and workers are not introduced. Native navigation works when enhancements are disabled.
- Candidate readiness checks marker 22, effective Tron, homepage and image CSP, both assets and the new PHP helpers locally. It does not depend on live Redlib or another search provider. Existing private bind, network/volume preservation, lock, backup and failure recovery logic remain. Release checks require the new runtime files and allow exactly two runtime scripts plus their two source-only Node fixtures.

`sh scripts/test.sh` passed: **12 PHP regression suites**, two Node state suites, stateful Docker API transaction simulations, isolated localhost HTTP controller tests and synthetic benchmarks. Fixtures use neutral text and generated 4×4 two-frame color patterns; no external search traffic or adult queries were used.

Redlib fixtures cover post text, dates, UTF-8 permalinks, malicious links, empty/error pages, fixed feed/search paths, reserved query prefixes, authoritative encrypted pagination and cursor rejection. ## Performance evidence

Local homepage HTTP: **50/50 successful responses**, concurrency 4, four PHP workers, median **3.90 ms**, p95 **8.25 ms**. These are loopback timings, not browser, Google, Redlib, VPS or TLS/NPM timings, and do not establish a controlled improvement over another release.

| Synthetic workload, 1,000 iterations | Median | p95 |
|---|---:|---:|
| Render homepage | 0.0685 ms | 0.0829 ms |
| Parse 50 Invidious videos | 0.0766 ms | 0.1059 ms |
| Parse 50 Binternet images | 0.2457 ms | 0.2822 ms |

Reported peak PHP allocation was 2 MiB for these synthetic workloads. Warm template caching produced byte-identical output. Measurements exclude image transfer/decoding, browser memory and rendering, provider round trips and VPS conditions. The animation concurrency limits are state-tested; device memory/CPU reductions are not measured claims.

## Remaining limits

Google and Brave can both rate-limit or change response formats. Brave image search currently has no continuation and filters formats locally, so a restrictive format may leave an empty page. Switching to fallback submits the query to Brave; the notice identifies this. The feature applies to new UI searches, not API consumers or an already-running image stream.

Live Redlib is unavailable at the check; Invidious/Binternet/Redlib playback and live provider quality are not guaranteed by fixture tests. A source parser cannot repair an unavailable upstream service.

No actual browser layout/scroll/mobile/accessibility acceptance, dependency vulnerability database scan, real Docker build, PHP 8.4/ImageMagick 7 runtime test or live VPS cutover/rollback was performed. Local runtime was PHP 8.3/ImageMagick 6; the image targets Alpine 3.24/PHP 8.4/ImageMagick 7. The deploy script performs candidate checks on the VPS when executed. Additional NPM CSP may independently block image enhancements. Existing non-atomic token consumption across separate tabs/processes and browser-history behavior remain documented in [operations](OPERATIONS-0.9.18.md). Keep rollback/private backups until they are no longer needed.
