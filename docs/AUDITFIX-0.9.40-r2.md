# Native fixture cleanup r2 — SecuritySearch 0.9.40

Application 0.9.40, asset 40, and the native audit inventory remain unchanged.
This is a locally reproduced fixture-restoration repair, not an assertion that
IONOS produced oversized configuration or that its r1 audit has passed.

## Defect and correction

R1 used the source-capture reader for restoration comparisons. That reader refuses
input beyond 1 MiB. After a fixture wrote 1,048,577 generated bytes, the comparison
raised before restoration. If the fixture had already raised an AssertionError,
the cleanup RuntimeError became the primary error and the generated file remained.

R2 keeps the 1 MiB limit for capturing the original source. Restoration uses a
separate exact comparator that reads no more than the original length plus one
byte. It handles short reads and detects trailing bytes. A generated file can be
larger without blocking restoration of the already captured original.

Exact source bytes and permissions are restored after normal completion or a
caught exception. The original exception is preserved when cleanup succeeds.
Linked/replaced files and storage failures remain hard failures. Unrelated files
are not restored. No guarantee is made for SIGKILL, power loss, concurrent hostile
same-user/root modifications, or failing storage. A failed/incomplete audit cannot
qualify as successful execution regardless of cleanup.

## Validation scope

Ten added tests cover oversized output, original exception identity, a 64 MiB
sparse generated file and measured read bounds, short reads, a late same-size
mismatch, trailing bytes, empty/truncated output, the unchanged initial capture
limit, KeyboardInterrupt propagation, and no content writes for unchanged bytes.
They extend the existing deploy-version suite; they do not replace an audit command.
No native runtime acceptance is implied by isolated filesystem/PHP fixture tests.

The r1 favicon host-isolation repair is retained byte-for-byte. Expected runtime
hashes, production config/generator/entrypoint, proxy/cache policy, 119-command
inventory, deployment gates and independent publisher verification remain intact.

## Execution

Use the self-contained r2 deployment launcher from ~/Downloads. Run --check-only,
then --audit-only. Accepted baselines include the exact r1 tree, original v0.9.40,
and the previously supported corrected v0.9.30 through v0.9.38 trees. Different
v0.9.40 trees are not equivalent merely because they have the same version string.

The launcher creates an ordinary repair commit when needed. No reset, amend,
stash, force-push, moved tag, or unverified configuration rewrite is performed.
Audit-only uploads/builds and retains resources, but does not replace production,
clean older objects, probe live providers or publish. It must complete 119/0 with
valid execution evidence. Normal deployment repeats the audit and live gates.
Publish only after DEPLOY COMPLETE, using the paired r2 publisher.

## Português do Brasil

A revisão r1 falhava ao restaurar a configuração quando o teste gerava mais de
1 MiB, podendo ocultar a exceção original. A revisão r2 separa a captura limitada
do original da comparação, que lê no máximo seu tamanho mais um byte. Os bytes e
permissões originais são restaurados; a falha original continua sendo uma falha.

Os dez novos casos integram a suíte existente. Os 119 comandos, os hashes esperados
e as verificações nativas/reais não foram reduzidos. A correção de isolamento dos
favicons da r1 permanece. Isso não comprova que a configuração da IONOS era grande
ou que a auditoria nativa foi aprovada. Use os launchers r2 correspondentes e publique
somente após DEPLOY COMPLETE. O modo --audit-only consome recursos, mas não troca
a produção nem remove objetos antigos.
