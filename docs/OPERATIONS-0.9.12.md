## What speed means

A 4–6 **millisecond error** can be an APCu cooldown rejection without a network
request. It is not a successful fast search. Conversely, a search taking 4–6
**seconds** may include Tor, TLS and provider processing. Measure HTTP status,
result count, time to first byte and total time together. Do not compare an error
with a successful search as a speed improvement.

Google remains selected by default. Its cold bootstrap and result hops now reuse
one cURL handle for the same request and egress, avoiding unnecessary connection
setup where the upstream permits reuse. Options are reset between hops; handles
are not shared between users or different proxies. This follows libcurl's
[documented reset behavior](https://curl.se/libcurl/c/curl_easy_reset.html).
Only `https://cse.google.com` on port 443 is accepted; redirects are not followed,
TLS verification stays enabled and decompressed responses are limited to 4 MiB.
Internal proxy addresses are not included in transport-error messages.

The Google and Google CSE aliases share their five-minute, query-free bootstrap
cache and 30-second anti-abuse cooldown when CX and egress match. A blocked
request cannot start another bootstrap. Concurrent waiters can consume the first
completed bootstrap for up to 24 seconds, subject to the whole request's
monotonic 25-second deadline; they do not make duplicate upstream calls.

There is no challenge solving, automatic provider substitution, direct fallback
from a configured Tor pool, persistent query cache or latency guarantee. One
same-egress retry for a transient 502/503/504 remains bounded by that deadline.
Google and Brave may still reject shared exits. Choose another provider explicitly
if necessary. Expired or consumed pagination links offer a fresh-search restart.

All five search APIs return 503 for caught provider exceptions. Explicit or saved
Google API selection without configured credentials fails before sending a query;
it does not silently become Google CSE. The fresh picker hides this unavailable option.

## Private proxy configuration

Pools stay outside Git and are mounted read-only. Entries use the existing
`type:host:port:username:password` format. Blank/comment lines are ignored;
surrounding whitespace is normalized. Unsupported types, malformed hosts/ports
and incomplete entries must throw before a network request. Never treat a typo
as permission to send a query directly. Run the proxy regression tests whenever
changing this parser. Do not print full pools, environment files or Docker Env.

## Lain and images

Asset version 15 invalidates older theme/controller URLs. The tracked
`static/misc/lain.gifv` is an actual GIF, not a video: serve it as `image/gif` with
static-asset caching. The original is about 8.7 MB; the first animated visit can
cost that download. It stays visible on mobile instead of being disabled solely
by screen width. The still-background control and reduced-motion/data preferences
provide an accessible lightweight alternative. Saved valid themes still win.

The six CSS views are Grid, Compact, Gallery, Feed, List and Filmstrip. Search,
filters, layout changes and ordinary pagination work without JavaScript. Optional
controllers add lightbox, animation previews and bounded infinite pagination.
Preview quality is the lighter default; originals are opt-in. Image requests
remain behind the existing validating proxy. Do not remove SSRF, MIME, byte or
decoder limits to make a broken upstream image appear successful.
Filmstrip uses the ordinary Next page link only: automatic vertical pagination
would otherwise fetch unseen horizontal cards prematurely.

## Status is a separate service

`/status/` is generated by the SecurityOps observer on CT119 and routed through
IONOS NPM over restricted private relays. It is not a Search provider health API.
Inspect the actual failed alias, response, probe time and snapshot age. A login
redirect can mean reachable; a 502 from the public login is a real gateway fault
even if the application works on its LAN address. Repair the proven route rather
than changing a 502 into an online badge. Probe transport failures with bounded
retries and preserve honest degraded/unknown states and history.

## Verify and deploy

Run all four network-free suites from the repository root:

```sh
php -d apc.enable_cli=1 tests/regression.php
php -d apc.enable_cli=1 tests/google-transport.php
php -d apc.enable_cli=1 -d disable_functions=curl_setopt tests/proxy-regression.php
php tests/provider-api-regression.php
```

Lint PHP and controllers; test normal and reduced-motion Lain on desktop/mobile,
compare animation frames, validate all six layouts without JS and test image-proxy
negative cases. Build an isolated candidate with the same private networks and
mounts as production. Check real provider results as well as error pages.

Keep a private configuration backup and previous container/image. Verify the
active container has not changed before cutover; retain the shared icon volume.
After deployment check HTTPS, MIME/cache/CSP, status and real searches again.
Never force-push or publish runtime secrets. See [release procedure](RELEASE.md).
